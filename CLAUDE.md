# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Earwig is an iPhone ear prompter (iOS 26+, SwiftUI) that reads a script into one Bluetooth earpiece slightly ahead of the presenter and follows what they actually say: it waits at a phrase end when they pause and picks them up again where they are. The script is pasted in (first of all a Cutaway project's `script.md`), rendered on the phone with word timings in the presenter's Personal Voice or a downloaded Apple voice before a take, and followed with Apple's on-device `SpeechAnalyzer`. The same engine drives an on-screen teleprompter. The author's builds go through TestFlight; the source is public for anyone to build, and an App Store version at a low price is planned (plan 011).

Sibling projects with the same conventions: `../Brollee` (local), and PhysiMate and Reclaim (private repos `bowerhaus/PhysiMate`, `bowerhaus/Reclaim`; read them with `gh api repos/bowerhaus/<repo>/contents/<path>`). PhysiMate is the closest match.

**The repo is public** (`bowerhaus/Earwig`), source-available under PolyForm Noncommercial 1.0.0 with an additional permission to use the app to make videos commercially (`LICENSE`). Everything committed and every issue is public: test fixtures and examples are made-up scripts, never the author's unpublished video scripts.

## Build Commands

```bash
xcodegen generate
xcrun simctl boot "iPhone 17"   # boot once per session to avoid ~60 s per run
xcodebuild -scheme Earwig -destination 'platform=iOS Simulator,name=iPhone 17' -derivedDataPath build/DerivedData test
swiftlint lint --quiet
uv run --with pillow scripts/app_icon/make_app_icon.py   # redraws the icon and the mark into the asset catalogue, and writes the critter's shape
uv run --with pillow scripts/readme/make_readme_images.py   # redraws the README's banner and following diagram from docs/screenshots/
scripts/release/testflight.sh             # bumps the build, archives, uploads to TestFlight, commits and tags testflight/X.Y.Z-N (Andy's yes first)
scripts/release/testflight.sh --dry-run   # archives without uploading and puts project.yml back
```

The upload needs a clean tree and the App Store Connect key's three Keychain items (service `bowerhaus.appstoreconnect`, accounts `key-id`, `issuer-id`, `key-p8`; the script prints the commands to store them, which Andy runs). Check they exist with `security find-generic-password -s bowerhaus.appstoreconnect -a <account>` and no `-w`, so no value is printed. The script's commit and tag are pushed by hand (`git push origin HEAD testflight/X.Y.Z-N`), each with Andy's yes.

Tests use Swift Testing (`import Testing`). Keep the build free of warnings and SwiftLint clean. A test that uses an in-memory `ModelContainer` must hold the container for as long as it uses its context, or the test host crashes. In the simulator, launch with `-EarwigDemo YES` (Debug builds) to open the Harbour Walk sample without taps; add `-EarwigListen YES` to open Listen on its start step once it is rendered, or `-EarwigTake YES` to start a take; `-EarwigNoListen YES` makes a take hear nothing, since the simulator cannot transcribe en-GB; `-EarwigListenGivesUp YES` makes listening give up ten seconds into a take. `-EarwigScreen YES` starts a Screen Only take on the demo script, and `-EarwigReads YES` makes a take hear the step read at 2.5 words a second, so the simulator shows the text following. `-EarwigRecordVideo YES` makes every take a video take (the simulator has no camera, so it frames on a placeholder and records nothing). `-EarwigNew YES` opens New on the Scripts screen, and `-EarwigEdit YES` opens Edit on the demo script (plan 015). `-EarwigCritter YES` makes the critter (plan 014) visit every screen two seconds after it appears and every 30 s while it stays, ignoring the Critter setting and the rest between visits. On the phone, launch without `-EarwigDemo`: the flag sets the navigation path at launch, and a tap then opens the Script screen twice. The README's still screenshots come from the simulator, with `xcrun simctl status_bar booted override --time 9:41 --batteryState discharging --batteryLevel 100`: it can't download voices, so the Script screen hides its missing-voice note there, and Settings is shot scrolled past the Voice group (plan 015). To capture the phone's screen, `xcrun devicectl device capture screenshot --device <UDID> --destination <path>`. Pass launch arguments to `devicectl device process launch` after `--`.

Audio, Bluetooth routing, Personal Voice, speech recognition and lock-screen behaviour cannot be verified in the simulator. Anything in the audio path must be checked on the author's iPhone 14 Pro. Claude installs it there directly, without opening Xcode (find the phone's UDID with `xcrun devicectl list devices`):

```bash
xcodebuild -scheme Earwig -destination 'id=<UDID>' -derivedDataPath build/DerivedData -allowProvisioningUpdates build
xcrun devicectl device install app --device <UDID> build/DerivedData/Build/Products/Debug-iphoneos/Earwig.app
xcrun devicectl device process launch --device <UDID> com.bowerhaus.Earwig
```

## Architecture

**Pattern:** MVVM with `@Observable` view models and SwiftData (PRD §7).

```
Views (SwiftUI) → ViewModels (@Observable) → Models (SwiftData)
                          ↓
   Services: ScriptParser, ScriptImporter, PhraseSplitter, VoiceRenderer, ScriptRenderer,
             VoiceCatalogue, Slate, Tones, AudioSessionManager, AudioEngineHost, Player,
             TakeAudio, StepPreview, Listener, HeardEvents, TakeHost, TakeSummary,
             ScriptTakeRecorder, ScreenText, CameraCapture, TakeRecording, RecordingStore
                          ↓
   Engine/: FollowEngine, Matcher, PresenterEstimate, Pacer, WordFolding, WordNormaliser,
            ScriptWords, FollowScript (pure Swift; time passed in)
```

- `Engine/` is pure Swift with time passed in on every call (`handle(_:at:)`, `tick(at:)`): **no SwiftUI, UIKit, SwiftData, AVFoundation, AVFAudio, Speech or Combine imports**; pass it plain values, never `@Model` objects or audio types. The `engine_purity` SwiftLint rule fails on those imports.
- The audio session is `.playAndRecord` with Bluetooth allowed for A2DP output only (`.allowBluetoothA2DP`, never `.allowBluetoothHFP`) and the built-in mic as preferred input. The earpiece is never the microphone.
- The take's step is rendered with word timings before it starts, in memory; the player is indifferent to where the audio came from. Phrase ends are reported on render (`.dataRendered`), not playback, so no output latency is added between phrases; progress is reported where the presenter hears it.
- `SpeechAnalyzer` gets untimed `AnalyzerInput` (stamped input ends its results). Interim results are one untimed block per stretch of speech; only finals time each word. Match interim text by order (plan 001 Results).
- Word markers from `AVSpeechSynthesizer.write` arrive by the marker callback or the `willSpeakMarker` delegate depending on the voice; `byteSampleOffset` is in bytes.
- The camera's `AVCaptureSession` sets `automaticallyConfiguresApplicationAudioSession = false` and never has an audio input, so it never touches the audio session, the route or the engine; a take's sound comes from the mic tap. One preview layer per take: adding a second to the running session holds the main thread for seconds (and a `Group`'s modifiers go to each child, so keep the camera in a real container).
- Swift Concurrency throughout; no third-party dependencies, Apple frameworks only.
- All colours live in `EarwigTheme`; views never define their own. The app runs in the light scheme (`EarwigTheme.scheme`), so text in lists and forms sets its colours itself (white labels, pale headers and values); toolbar buttons hide iOS's glass (`sharedBackgroundVisibility(.hidden)`) and use `toolbarCircle()`, `toolbarCapsule()` or `DoneButton`.
- UK spelling in UI text and code names (`normalise`, `colour`).

## Rules

- **One plan per branch.** Each stage in PRD §12 is one plan (`plans/NNN-name.md`), one branch, one GitHub issue and one PR. A plan ends with a filled **Results** section where a spike or device check calls for one, and the PRD gets a version bump and a Document History row when a stage completes.
- **`progress.md` is scratch state for the plan in flight**, overwritten at the start of a plan and emptied to a stub when it completes. Nothing that must outlive the plan goes there; that belongs in the plan's Results, the PR body or the PRD's Document History.
- **Never guess a device result.** Verdicts on voice, earpiece, recognition and feel come from the author; record only what he reports.

## Git Workflow

- Claude commits locally at sensible points without asking.
- Pushing, opening a PR and creating a GitHub issue each need the author's yes.
- Branch per plan, PR to `main`.
- Releases: an annotated tag `vX.Y.Z` on `main` at the merge commit (`git tag -a vX.Y.Z -m "Earwig X.Y.Z"`), pushed, and `gh release create vX.Y.Z --prerelease --title "Earwig X.Y.Z" --notes-file <notes>`, notes from the PRD's Document History since the last release and the known issues; no binary. Pushing the tag and creating the release each need Andy's yes. `MARKETING_VERSION` in `project.yml` is the version; the TestFlight script bumps `CURRENT_PROJECT_VERSION` and tags `testflight/X.Y.Z-N`.
- Keys: the app has none. The App Store Connect key (the team's, shared with PhysiMate) lives in the macOS Keychain under service `bowerhaus.appstoreconnect`, used only by `scripts/release/testflight.sh`. Claude never reads, prints or handles a key's value.
